# Al-Haydari Lecture Catalog

An English-language digital catalog of the Arabic lectures on the
[al-Haydari YouTube channel](https://www.youtube.com/@alheydari) (Sayyid Kamal al-Haydari):
~2,750 videos and ~1,900 hours on philosophy, theology, jurisprudence, Qur'anic exegesis and hadith studies.

For every video the catalog provides:

- an English title, description, summary, key points and references (Qur'an passages, people, works);
- a **full, timestamped English translation of the audio**, synced to the YouTube player;
- placement in a two-level **topic taxonomy** (independent of the channel's playlists) and in its lecture series;
- full-text search across titles, summaries and transcripts.

```
pipeline/   Python ingestion pipeline (yt-dlp → Gemini → JSON)
data/
  catalog/  pipeline output, committed (source of truth for the site)
  raw/      audio and chunk caches (gitignored)
  site/     merged JSON for the site, generated by `catalog export` (gitignored)
site/       Astro static site + Pagefind search
```

## Pipeline

Requirements: Python 3.12+, [uv](https://docs.astral.sh/uv/), `ffmpeg`, Node.js (yt-dlp uses it to solve YouTube's JS
challenges), and a Google AI Studio API key in `.env` (see `.env.example`).

```sh
cd pipeline
uv sync
uv run catalog sync          # list videos + playlists        → data/catalog/channel.json
uv run catalog meta          # per-video metadata (~2-3 h)    → data/catalog/meta/
uv run catalog enrich        # English titles/summaries/topics → data/catalog/enrich/
uv run catalog transcribe --limit 20     # audio → English transcripts → data/catalog/transcripts/
uv run catalog taxonomy      # design taxonomy + assign topics → data/catalog/taxonomy.json, topic_assignments.json
uv run catalog export        # merge for the site             → data/site/
uv run catalog status        # coverage report
```

Every stage is **idempotent and resumable**. A video is done for a stage when its output file exists, so you can stop
any command and run it again later. Transcription also caches each audio chunk's translation in `data/raw/chunks/`.

### How transcription works

1. yt-dlp downloads the smallest audio-only stream.
2. ffmpeg splits it into ~12-minute chunks at the nearest silence (`CATALOG_CHUNK_SECONDS`), then re-encodes each chunk
   as 16 kHz mono Opus (~2 MB).
3. Each chunk goes to Gemini with a translator system prompt and a terminology glossary
   (`pipeline/catalog/glossary.yaml`). The model returns structured JSON: segments with timestamps, speaker, kind
   (speech, Qur'an, hadith, poetry, supplication) and key Arabic terms. The tail of the previous chunk is passed along
   as context.
4. Timestamps are made absolute, clamped and checked. A chunk whose translation looks truncated (low coverage or word
   count) is retried.
5. The full transcript is then fed to the enrichment step for a summary, key points, topics and references.

A one-hour lecture takes about 5 requests: ~95k input tokens and ~30k output tokens.

### Gemini quota and models

- Models are set by environment variables (`CATALOG_TRANSCRIBE_MODEL`, etc.). When a model is overloaded (HTTP 503),
  requests fall back along `CATALOG_FALLBACK_MODELS`.
- On the free tier, the pipeline stops cleanly when the daily quota runs out (`QuotaExhausted`). Re-run the same
  command the next day and it resumes. `--order playlist|views|newest|oldest|shortest` and `--limit` decide what
  gets transcribed first.
- Videos without a transcript are catalogued from their title and description, in batches of 20 per request. Once
  transcribed they are re-enriched automatically.

### Manual corrections

`pipeline/catalog/overrides.yaml` assigns topics to specific videos; overrides beat the model's output. To fix a
translation, edit the JSON under `data/catalog/` directly. The stages never overwrite existing outputs unless run with
`--refresh` / `--rebuild`.

## Site

```sh
cd pipeline && uv run catalog export   # always run after pipeline changes
cd ../site
npm install
npm run dev                            # http://localhost:4321 (search needs a build)
npm run build                          # static site + Pagefind index → site/dist
npm run preview
npx playwright test                    # smoke tests against the build
```

On Alpine/musl, install a system Chromium and run `CHROMIUM_PATH=/usr/bin/chromium npx playwright test`.

Pages:

- `/`: home
- `/topics/…`: topic taxonomy
- `/series/…`: playlists, in episode order
- `/videos/`: client-side filter and sort over all videos (topic, series, year, length, transcript)
- `/v/<id>/`: video page with player, summary, references and the interactive transcript (click a timestamp to seek;
  the current segment highlights; Arabic terms toggle; .txt download)
- `/search/`: Pagefind full-text search

SEO: sitemap, canonical URLs, OpenGraph, and `VideoObject` JSON-LD.

## Deployment

`.github/workflows/deploy.yml` builds from the committed `data/catalog` and publishes to GitHub Pages. Set the repo
variables `SITE_URL` / `BASE_PATH` for a custom domain. Any static host works: run `npm run build` and upload
`site/dist`.

To refresh the catalog: run `catalog sync && catalog meta && catalog enrich && catalog transcribe … && catalog taxonomy`,
then commit `data/catalog` and push.

## Disclaimer

Translations are machine-generated and unreviewed. This project is independent of Sayyid al-Haydari and his office,
